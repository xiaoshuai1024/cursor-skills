# 分析细则 — mstodo-topic

三维评估 × 三档（✅/⚠️/❌）→ 档位结论 → 报告。分析是定性判断，由模型读快照 JSON 完成，不打分脚本。

## 一、三维评估

### 1. 仿写价值（能不能学）

| 判什么 | ✅ | ⚠️ | ❌ |
|--------|----|----|----|
| 结构可迁移 | 钩子/叙事骨架/数据呈现方式清晰可拆 | 结构平庸但局部手法可借 | 纯观点宣泄/情绪文，无结构可拆 |
| 信息增量空间 | 换成本站源码/实操证据能讲得更深 | 需补实验/补源码才立得住 | 已被讲透，无增量角度 |
| 源内容质量 | 附 URL 且内容扎实（先渲染抓取正文核对） | URL 失效/未附，仅凭待办文字判断 | 明显水文/过时结论 |

待办附 URL 时：先抓正文做结构参照（复用 tech-topic 的渲染抓取思路），报告里注明「源已核对」；URL 取不到就按 ⚠️ 处理并注明。

### 2. 潜力（值不值得做）

- **受众面**：泛开发者痛点 → ✅；垂直小众但本站读者精准 → ⚠️ 起；纯个人记录（无共性）→ ❌。
- **时效性**：热点窗口内 → 加档；长青主题 → 正常；已过气技术 → 降档。
- **存量重合**：对照 `content/posts/` 标题 + tags——写过同题 → 降档或转「续写/翻新视角」并注明旧文；没写过 → 正常。
- **可视化素材潜力**：流程/架构/代码/截图/数据多的 → 视频方向加档；纯概念思辨 → 视频降档。

### 3. 方向匹配度（对不对路）

博客方向 = 前端 / 全栈 / AI 开发工程实践。关键词参考（命中任一即沾边）：

- 前端：React / Vue / 浏览器 / 渲染 / 工程化 / 构建 / 性能 / CSS / 跨端
- 全栈：Node / 服务端 / 数据库 / 部署 / DevOps / 架构 / 网关 / 缓存 / 消息队列
- AI 开发：LLM / Agent / RAG / Claude / Cursor / Codex / 提示词 / MCP / 微调 / 推理 / AI 编程 / 语音合成
- 工程实践：源码解读 / 踩坑 / 性能优化 / 自动化管线 / 效率工具

完全不沾边默认 ❌；确属高潜力泛技术热点可破例，**必须写明破例理由**。

## 二、档位矩阵

| 匹配度 | 仿写价值 | 潜力 | 档位 |
|--------|----------|------|------|
| ✅ | ✅ | ✅ | ✅ 文章+视频（素材可视化弱则 ✍️ 仅文章） |
| ✅ | ✅ | ⚠️ | ✍️ 仅文章（或入系列储备） |
| ⚠️ | ✅ | ✅ | 🎬 仅视频（轻快口播试水）或 ✍️，看素材形态 |
| ❌ | — | — | ❌ 不适合（除非破例，注明理由） |

## 三、报告模板

```markdown
# 待办选题分析 — <清单名>（YYYY-MM-DD）

> 快照: .mstodo-topic/snapshots/<文件>.json ｜ 未完成 N 条，分析 M 条

## 逐条分析

### 1. <待办标题>
- 原文: <正文摘录，≤120 字；有 URL 注明并标记是否已核对>
- 仿写价值: ✅/⚠️/❌ —— <一句话依据>
- 潜力: ✅/⚠️/❌ —— 受众面/时效/存量重合/可视化素材
- 方向匹配: ✅/⚠️/❌ —— <命中方向或说明为何不沾边>
- **档位: ✍️ 仅文章** —— <理由一句>
- 建议: <动作；存量重合时给出旧文 relref>

#### 文章大纲（✍️/✅ 项必附）
- 标题候选: ①… ②… ③…
- 类型: 教程型/深度型/踩坑型/最佳实践型/观点型
- 骨架: H2 × N，每节一句要点 + 配图点（素材撑不撑得起要讲透的正文，要说明；篇幅由内容定，不设字数门槛）

#### 口播稿 + 分镜（🎬 项必附；✅ 项视频阶段再做，此处只给视频可行性一句）
- 口播稿: 提问式开头（「问你一个问题」/「你有没有想过」二选一）→ 正文回收 → 结尾四段结构
- 钩子 → 回收映射表（无回收点的钩子不许埋）
- 分镜: 时间轴 × 画面（含动画/BGM 情绪档/音效触发点/转场类型三列）

## 汇总

| # | 待办 | 档位 | 优先级 | 一句话 |
|---|------|------|--------|--------|

## 写回记录

| taskId | 档位 | 备注 | 状态 |
|--------|------|------|------|
```

## 四、诚实原则

- ❌ 项的理由必须具体（「AI 管线私有实现无可参照源码，结构拆不动」），禁止「不太合适」「一般」这类含糊话。
- 全部不适合就明说「本批无适合项」，不硬凑。
- 素材撑不起教程/深度型讲透所需体量的要直说（拆系列或补素材），不装够。
- 口播/分镜模板的对齐基准是 video-generation skill 的现行规范；拿不准的规范项以那边为准，不在这边另立。
