# 公众号留存规范（平台适配层）

> 本文件与掘金爆款化（`post-types-guide.md` 第十章）同构：**基础写作规范管文章本身，本文件管同一篇文章发公众号怎么留住人**。通用规则（段落 ≤4 行、1500 字配图、反直觉开场、结论式收尾）引用不复制，以 style-guide 为准。
>
> 留存漏斗：**推送曝光（标题+摘要）→ 首屏 3 段 → 滚动阅读 → 完读 → 转化**。每一层的流失都不可逆，逐层过。

## 〇、流量来源与算法考核（2026-08-28 调研增补）

> 📊 依据：openspec `wechat-traffic-research`（调研决策类变更，含全部来源）。先搞清流量从哪来、算法考核什么，后面各层规则才有靶子。

- **流量结构**：公众号已从「订阅优先」转向**「算法推荐 + 社交裂变」双引擎**，非粉丝流量可占阅读的 50%-90%，粉丝数不设限。文章发布后先进冷启动池（约 500-1000 次曝光）赛马，完读与互动达标才晋级更大流量池。
- **算法信号**：「在看」不只是文末动作，是撬动「看一看」社交推荐池的信号；**搜一搜按「标题 / 副标题 / 关键词密度」抓取**，是长尾流量入口；**账号垂类一致性决定初始权重**——选题方向稳定本身就是算法资产（合集挂对之外的第二层含义）。
- **考核排序（运营圈共识，非官方文档）**：完读率 > 互动（在看/分享/关注）> 打开率 > 停留时长，粉丝数权重倒数。完读 <30% 推荐终止、≥50% 进中级池、>65% 持续追加（基准线见第七节）；点开秒退判低质停推。
- **推论**：打开层决定「送达的人里多少点进来」，完读层决定「算法给不给人」——两层都要过但杠杆不同：**打开层靠标题/摘要/封面（与篇幅无关），完读层靠首屏/节奏/长度（长度决策见第三节）**。

### 自有基线实证（2026-08-29，wechat-analytics 首批数据）

> 📊 依据：openspec `wechat-analytics-skill` 首跑，12 篇统计完整文章 + 63 天账号序列（`make wechat-analytics` 日频更新）。本号自己的数据，优先级高于上面所有外部调研口径；样本标注：完读/互动明细 n=3（详情接口仅发表 30 天内），账号级结构 n=63 天。

- **流量结构实证**：推荐占阅读 **83%-95%**（63 天逐周），搜一搜 1%-6.4%，粉丝消息打开 3%-4%——比调研口径（非粉丝 50-90%）更极端，**本号阅读量 = 推荐引擎给多少，粉丝盘基本只是底仓**。
- **完读全线不达线（最大卡点）**：有明细的 3 篇完读 28.7% / 19.9% / 15.6%，全部 <30% 终止线；字数与完读强负相关（5266→28.7%、7181→19.9%、11727→15.6%）。**平均阅读时长仅 55-87 秒**——7000+ 字的长文，读者只消费开头 400-700 字。
- **互动远超基准（被浪费的强信号）**：分享率 9.7%-14.5%（基准 1%-3% 的 3-10 倍）、收藏率 2.8%-8.3%——内容传播性极强，卡住放大的只有完读。
- **爆文解剖（唯一一次引爆，08-06 插件榜文）**：发布当天仅 25 阅读（粉丝盘），**第 2-3 天推荐引擎引爆**（230→613→594→505，持续约 10 天），5309 阅读、+80 关注——占 63 天全部关注转化（87 人）的 **92%**。推论：①推荐引擎有冷启动考核期，发布后首波数据决定推不推；②**粉丝增长≈爆文频率**，日常文章涨粉 1-6 人；③榜单/清单型选题已验证（选题画像见第三节长度实证后的「选题优先级」）。
- **对本号规则的含义**：①长度决策收紧为「>4000 默认压缩变体」（第三节，2026-08-29 修订）；②新增 90 秒规则（第二节）；③关注引导必须带「持续价值理由」（第六节）——清单型 +80 vs 单篇清单 +1 的差别就是「以后还有」的理由。

## 一、打开层：标题与摘要变体

公众号标题**不是**博客标题。博客标题按 SEO 写（25-30 字、关键词前置），在公众号推送里会被折叠截断，钩子正好被截没。

### 标题（`wechat_title`）

- **≤25 字**（推送折叠线，platform-limits 数据支撑），**钩子/冲突点放前 13 字**（会话列表可见域，经验值）
- **含 1 个可搜关键词**（2026-08-28 增补）：搜一搜按标题关键词密度抓取，标题里保留读者会搜的实体词（工具名/技术名词，如 Claude Code、IndexTTS），关键词前置或紧跟钩子——别为钩子把可搜词全挤掉
- 不直接复用博客 SEO 长标题；metadata-optimizer 出候选时同步产出 `标题_公众号` 变体，写 front matter 可选字段 `wechat_title`
- 禁标题党五类：混淆官方 / 煽动 / 夸大 / 冒充 / 对抗审核——触发限流且透支信任，判废
- 情绪档位沿用第 2 步定规：停在第 2 档（打脸感可以，「震惊级」不行）

### 摘要（`wechat_digest`）

- digest 不填时公众号默认抓正文前 54 字——**必填**。载体 = front matter `wechat_digest`（缺省回退 `description`）
- **前 40 字 = 推送列表可见域（经验值）**，承担打开转化：含痛点或硬数字，不是背景铺垫
- 写法参照 description 三段式（痛点 + 给什么 + 数字背书），但把「痛点/数字」压进前 40 字

```
❌ 本文介绍 Claude Code 的 skill 系统的设计思路与使用方法，并给出实践建议。（主题复述，无打开理由）
✅ Claude Code 的 skill 不是提示词模板。拆了它的加载链路后，我改了 3 处用法，省下每天重复交代的时间。（前 40 字内有反差 + 数字）
```

### 封面（`cover.png`，2026-08-28 定规：公众号封面独立定制，禁止直搬）

**封面和标题一样是打开层的转化件**，且是列表页第一视觉。两类错误做法都判废：

- ❌ **视频封面直搬**：视频封面为 1920×1080 视频信息流设计（EP 角标/贴纸带/要点行/「看完整流程」CTA），公众号卡片展示约 2.35:1 小图——上下沿被裁、贴纸带小图下是不可读噪点、视频专属元素（角标/CTA/系列栏）全是错位信息
- ❌ **首图架构图/截图兜底**：架构图无钩子、文字在封面尺寸下不可读，点击转化趋近于零

**正解：用封面生成脚本独立定制**（参考抖音封面的大字钩子设计语言，按公众号卡片规格重做）：

```bash
python .agents/skills/blog-writing/scripts/make_cover.py \
  --slug <slug> --line1 "同一个问题" --line2 "贵 30 倍" \
  --subtitle "DeepSeek Harness 缓存省钱的三条纪律" --tags "DeepSeek,缓存,省钱"
```

- 画布 1800×1000（9:5 = prepare.py 原生尺寸，零裁损）；**居中构图**——全部文字落在中央 2.35:1 安全区（会话列表裁切带）**且在 1:1 中心带内**（朋友圈卡/次条是 1:1 中心裁切，约保留 x 400-1400，左对齐排版会被切掉左侧；2026-08-28 调研修正，来源见壹伴/数英封面规范）
- 设计即大字风格定规 + 抖音缩略锚点移植：**双行大字居中**——第一行白色 96px 级；第二行默认**黄底深字色块锚点**（微倾斜 -2°，v4 封面标准「一图一主角·缩略锚点」同款，`--style block` 默认；`--style glow` 青色辉光备选）；副标题 36px；标签 ≤3 个 pill；无角标无 CTA 无贴纸带；一图一焦点，小图下只剩色块一句话也成立
- 产物 `static/images/<slug>/cover.png` 公众号与博客共用；文章正文首图放它（prepare.py 取首图裁封面）
- 批量：`--spec specs.json`（`[{slug,line1,line2,subtitle,tags[]}]`，style 缺省 block）
- ℹ️ mp 支持一篇文章两张封面（头条 2.35 大图 + 次条/小图 1:1），星标常读用户看大图、其他用户看小图；当前管线只传一张（首图裁 9:5），1:1 专用封面留作后续增强

## 二、首屏层：前 150 字定生死

公众号没有 TOC，标题 + 封面吃掉首屏一半，**正文前 150 字决定读者划不划走**。

> 📊 数据支撑（2026-08-26 调研）：公众号实测**读者在正文 5%-15% 位置跳出最多**，中间内容几乎无跳出——过了第一屏的人大概率读到结尾（人人都是产品经理数据优化案例）；NN/g 眼动研究：用户平均只读网页文本的 **20%**。首屏是全程留存率最高杠杆。

- 前 150 字内必须同时出现：**问题定义**（这篇解决什么）+ **钩子**（反直觉发现 / 数据 / 痛点场景）
- 博客的「反直觉发现开场 + 回收」定规（2026-08-18）直接沿用——多数情况已合规，本层只加「首屏可见性」检查：钩子段够不够靠前，别让铺垫把它推出首屏
- **首屏配一张图**：配图规则（1500 字/图）之上，公众号版第一屏内尽量有一张总览图/架构图锚住视线（博客端已有「开头前 800 字必有总览图」规则，公众号更严）
- 禁寒暄式 / 背景铺垫式开头（「在 AI 快速发展的今天」）——这在任何平台都是 3 秒关页面

自检方法：手机上打开预览，不滚动看到的第一屏，能不能让读者知道「这篇讲什么 + 值得往下看」。看不到问题定义就压缩铺垫或把钩子段前置。

**90 秒规则（2026-08-29 自有数据增补）**：本号平均阅读时长实测仅 55-87 秒 ≈ 400-700 字——**按「读者只给你 90 秒」设计全文前段**：前 600 字内必须完成「问题 + 钩子 + 本文最重要的那句判断/结论」（结论前置，不是文末才揭晓）。自检：只读前 600 字，读者能否复述「这篇的核心判断是什么」？不能 = 核心结论还埋在中后段，提上来。

## 三、长度决策与节奏层：推送版多长、滚动怎么锚

### 长度决策：公众号版三档（2026-08-28 调研增补；2026-08-29 自有数据收紧）

> 📊 依据：篇幅不直接影响阅读量，走「篇幅 → 完读率 → 推荐流量 → 阅读量」间接链路；800-2000 字完读最佳区间、大几千字长文完读率拉胯（运营侧统计与实操共识）；但高质量人群偏好深度内容、收藏是强质量信号。**博客端「篇幅由观点和内容决定」定规（2026-08-26）不动**，本决策只管推送出去的公众号版。
>
> 📊 **2026-08-29 自有数据收紧**：首批 12 篇统计完整文章中 11 篇 >4000 字直发，有明细的 3 篇完读 28.7%/19.9%/15.6% **全 <30% 终止线**，且字数与完读强负相关（5266→28.7%、7181→19.9%、11727→15.6%，n=3）。方向与外部调研一致——「直发+结构补偿」不再是默认路径。

同步公众号前按成文字数定档（**发文节奏不变：压缩变体不增减篇数，日更照常**）：

| 档位 | 条件 | 动作 |
|---|---|---|
| 直发 | ≤2500 字 | 不做额外处理，过本清单即可 |
| 压缩变体 | 2500-4000 字 | 公众号版砍重复铺垫、长代码、次要支线，压到 ≤2500；**核心论证一个不砍**，博客版保持原样 |
| **压缩变体（默认）** | **>4000 字** | **2026-08-29 修订：默认出压缩变体压到 ≤2500-4000**（砍法同上，核心论证/核心数据/可收藏资产一个不砍）。拆系列仅当内容确实装不下（多个独立主题）才用——拆系列会增加发文数，与既定日更节奏冲突，不作为默认。长文直发改为**例外**：强连贯论证不便压缩时才直发，必须全款支付结构补偿（首屏 150 字 + 小标题间隔 ≤1200 字 + 每节段首承重 + 文末收藏资产 + 90 秒规则），并在 link-map 备注记「长文直发豁免理由」供回看对照 |

三档的最终判据仍是**推送版完读率能否过 30% 线**；压缩变体档跑出 ≥2 篇对照数据后复核本收紧是否成立（openspec `wechat-analytics-skill` tasks Phase 5）。

**选题优先级（同一批数据的画像，观察级 n=1 爆文，不作硬规则）**：清单/榜单型（5309 阅读、+80 关注）与对比决策型（完读 28.7% 全账号最好、仅 5266 字）是本号已验证的两类高表现选题——同类选题出现时优先押注并**按压缩变体长度写公众号版**。

### 节奏层：滚动阅读的进度感

手机滚动没有「文档感」，读者靠**小标题和图**感知进度和位置。

- **相邻二级标题间隔 ≤1200 字（经验值）**：长章节拆小节，给滚动中的读者「进度锚点」。拆不出小节说明这节在堆料，先按第 3 步骨架法重排
- **代码块 ≤15 行**：手机上长代码块横向滚动体验极差。超长改「关键片段 + 完整版见原文 / 仓库链接」——反正博客版有完整代码，公众号版只留讲解必需的几行
- 段落 ≤4 行、连续纯文字 ≤1500 字补图：沿用博客规范（配图在公众号自动转 PNG，链路已有）

## 四、扫读层：段首承重 + 过桥句（2026-08-26 调研增补）

> 📊 依据：NN/g 眼动研究——用户平均只读网页文本 **20%**，扫读时走 F-pattern（先横扫标题和段首，再沿左侧竖扫）；结论是 scannable text：段首前置关键词、每段一个观点、倒金字塔（结论先行）。

- **段首承重**：每段第一句 = 该段结论/要点，支撑句跟在后面。扫读测试：只读「小标题 + 每段第一句 + 加粗」串起来，文章逻辑是否还成立？成立 = 扫读可用；不成立 = 把埋在段中间的结论提上来
- **每段一个观点**：一段塞两个论点，扫读者两个都抓不到——拆段（与段落 ≤4 行规则同向）
- **过桥句（bucket brigade）**：段落间用**指向具体内容的短句**衔接，替代干巴巴的过渡——「先看数据」「下一行才是关键」「更麻烦的在后面」
  - ⚠️ 合规边界：过桥句不是「但是/然而/接下来」这类空过渡词（de-ai-smell 禁），更不是设问句（「那怎么办？」禁）——判据：**句子里有具体内容指向**（指数据、指下一段的实体），不是纯语气垫词
- **关键词加粗克制**：扫读者的视觉锚点，沿用 de-ai-smell 每节 ≤2 处——加粗越少，被加粗的越有效

## 五、钩子兑现层：承诺了就要还

开头钩子作的承诺，**必须逐节兑现**——与视频「钩子 → 回收映射表」定规同构（2026-08-24）：

- 写稿时列**钩子 → 回收清单**：哪个承诺（「后文会讲清 X」「第二章给你答案」）、在哪节兑现。**无回收点的钩子不许埋**
- 章节转场给期待：用**陈述式预告**（「下一节会看到这三个命令怎么互相咬合」），制造往下读的动力
- ⚠️ 转场预告**不是设问句**——「那怎么解决呢？」是自问自答套路（de-ai-smell 行为规范 #10 禁），陈述式预告直接说下一节有什么

钩子清单是写稿工作产物（稿内 HTML 注释或 .tmp 即可），不进正文、不进 front matter。

## 六、转化层：结尾在看 / 关注（合规红线）

> 📊 转化逻辑（2026-08-26 调研）：**干货驱动收藏，社交货币驱动转发**——实用型内容读者收藏自用（收藏率是实用价值指标），转发发生在内容「替读者表达了观点 / 转出去对他有用」时（社交货币）。技术号的动作词只有**在看 / 关注**（禁转发引导），转发靠内容本身的社交货币属性，不靠 CTA。

结论式收尾定规不动（最后一段连贯文字）。转化引导是**结论段之后的独立一小段**：

- **价值锚定式**：「如果这篇帮你省了排查时间，点个在看让我知道」——先给价值再要动作
- **单动作**：一篇只要一个动作（在看 或 关注），与视频 CTA「价值锚定单动作」定规同思路
- **关注必须带「持续价值理由」（2026-08-29 自有数据增补）**：要关注动作时，理由写「读者关注后能得到什么」——下一篇预告（系列化：「这个系列下一期拆 X」）/ 清单持续更新（「这份清单我会持续维护，更新了第一时间发」）/ 同类选题定位（「这里持续拆 AI 编程工具的源码」）。数据依据：榜单清单文 +80 关注 vs 单篇清单文 +1——差别就是「以后还有」；只说「点个关注」没有持续理由 = 白要动作
- **收藏触发点**：文中至少一处「可收藏资产」——命令速查 / 对比表 / 决策树 / 配置清单（掘金章「获得感」表格的公众号落地），并在转化段点出（「文中的 X 表可以直接收藏」）——收藏是完读之外的强质量信号
- **转发属性写法**（不引导转发，但让内容值得转）：观点段敢下判断、替读者说出他在团队里说不出的话（「这套流程推行不动，问题多半不在工具」）——读者转发的是「我想说的这句话」
