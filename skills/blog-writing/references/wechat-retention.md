# 公众号留存规范（平台适配层）

> 本文件与掘金爆款化（`post-types-guide.md` 第十章）同构：**基础写作规范管文章本身，本文件管同一篇文章发公众号怎么留住人**。通用规则（段落 ≤4 行、1500 字配图、反直觉开场、结论式收尾）引用不复制，以 style-guide 为准。
>
> 留存漏斗：**推送曝光（标题+摘要）→ 首屏 3 段 → 滚动阅读 → 完读 → 转化**。每一层的流失都不可逆，逐层过。

## 一、打开层：标题与摘要变体

公众号标题**不是**博客标题。博客标题按 SEO 写（25-30 字、关键词前置），在公众号推送里会被折叠截断，钩子正好被截没。

### 标题（`wechat_title`）

- **≤25 字**（推送折叠线，platform-limits 数据支撑），**钩子/冲突点放前 13 字**（会话列表可见域，经验值）
- 不直接复用博客 SEO 长标题；metadata-optimizer 出候选时同步产出 `标题_公众号` 变体，写 front matter 可选字段 `wechat_title`
- 禁标题党五类：混淆官方 / 煽动 / 夸大 / 冒充 / 对抗审核——触发限流且透支信任，判废
- 情绪档位沿用第 2 步定规：停在第 2 档（打脸感可以，「震惊级」不行）

### 摘要（`wechat_digest`）

- digest 不填时公众号默认抓正文前 54 字——**必填**。载体 = front matter `wechat_digest`（缺省回退 `description`）
- **前 40 字 = 推送列表可见域（经验值）**，承担打开转化：含痛点或硬数字，不是背景铺垫
- 写法参照 description 三段式（痛点 + 给什么 + 数字背书），但把「痛点/数字」压进前 40 字

```
❌ 本文介绍 Claude Code 的 skill 系统的设计思路与使用方法，并给出实践建议。（主题复述，无打开理由）
✅ Claude Code 的 skill 不是提示词模板。拆了它的加载链路后，我改了 3 处用法，省下每天重复交代的时间。（前 40 字内有反差 + 数字）
```

## 二、首屏层：前 150 字定生死

公众号没有 TOC，标题 + 封面吃掉首屏一半，**正文前 150 字决定读者划不划走**。

> 📊 数据支撑（2026-08-26 调研）：公众号实测**读者在正文 5%-15% 位置跳出最多**，中间内容几乎无跳出——过了第一屏的人大概率读到结尾（人人都是产品经理数据优化案例）；NN/g 眼动研究：用户平均只读网页文本的 **20%**。首屏是全程留存率最高杠杆。

- 前 150 字内必须同时出现：**问题定义**（这篇解决什么）+ **钩子**（反直觉发现 / 数据 / 痛点场景）
- 博客的「反直觉发现开场 + 回收」定规（2026-08-18）直接沿用——多数情况已合规，本层只加「首屏可见性」检查：钩子段够不够靠前，别让铺垫把它推出首屏
- **首屏配一张图**：配图规则（1500 字/图）之上，公众号版第一屏内尽量有一张总览图/架构图锚住视线（博客端已有「开头前 800 字必有总览图」规则，公众号更严）
- 禁寒暄式 / 背景铺垫式开头（「在 AI 快速发展的今天」）——这在任何平台都是 3 秒关页面

自检方法：手机上打开预览，不滚动看到的第一屏，能不能让读者知道「这篇讲什么 + 值得往下看」。看不到问题定义就压缩铺垫或把钩子段前置。

## 三、节奏层：滚动阅读的进度感

手机滚动没有「文档感」，读者靠**小标题和图**感知进度和位置。

- **相邻二级标题间隔 ≤1200 字（经验值）**：长章节拆小节，给滚动中的读者「进度锚点」。拆不出小节说明这节在堆料，先按第 3 步骨架法重排
- **代码块 ≤15 行**：手机上长代码块横向滚动体验极差。超长改「关键片段 + 完整版见原文 / 仓库链接」——反正博客版有完整代码，公众号版只留讲解必需的几行
- 段落 ≤4 行、连续纯文字 ≤1500 字补图：沿用博客规范（配图在公众号自动转 PNG，链路已有）

## 四、扫读层：段首承重 + 过桥句（2026-08-26 调研增补）

> 📊 依据：NN/g 眼动研究——用户平均只读网页文本 **20%**，扫读时走 F-pattern（先横扫标题和段首，再沿左侧竖扫）；结论是 scannable text：段首前置关键词、每段一个观点、倒金字塔（结论先行）。

- **段首承重**：每段第一句 = 该段结论/要点，支撑句跟在后面。扫读测试：只读「小标题 + 每段第一句 + 加粗」串起来，文章逻辑是否还成立？成立 = 扫读可用；不成立 = 把埋在段中间的结论提上来
- **每段一个观点**：一段塞两个论点，扫读者两个都抓不到——拆段（与段落 ≤4 行规则同向）
- **过桥句（bucket brigade）**：段落间用**指向具体内容的短句**衔接，替代干巴巴的过渡——「先看数据」「下一行才是关键」「更麻烦的在后面」
  - ⚠️ 合规边界：过桥句不是「但是/然而/接下来」这类空过渡词（de-ai-smell 禁），更不是设问句（「那怎么办？」禁）——判据：**句子里有具体内容指向**（指数据、指下一段的实体），不是纯语气垫词
- **关键词加粗克制**：扫读者的视觉锚点，沿用 de-ai-smell 每节 ≤2 处——加粗越少，被加粗的越有效

## 五、钩子兑现层：承诺了就要还

开头钩子作的承诺，**必须逐节兑现**——与视频「钩子 → 回收映射表」定规同构（2026-08-24）：

- 写稿时列**钩子 → 回收清单**：哪个承诺（「后文会讲清 X」「第二章给你答案」）、在哪节兑现。**无回收点的钩子不许埋**
- 章节转场给期待：用**陈述式预告**（「下一节会看到这三个命令怎么互相咬合」），制造往下读的动力
- ⚠️ 转场预告**不是设问句**——「那怎么解决呢？」是自问自答套路（de-ai-smell 行为规范 #10 禁），陈述式预告直接说下一节有什么

钩子清单是写稿工作产物（稿内 HTML 注释或 .tmp 即可），不进正文、不进 front matter。

## 六、转化层：结尾在看 / 关注（合规红线）

> 📊 转化逻辑（2026-08-26 调研）：**干货驱动收藏，社交货币驱动转发**——实用型内容读者收藏自用（收藏率是实用价值指标），转发发生在内容「替读者表达了观点 / 转出去对他有用」时（社交货币）。技术号的动作词只有**在看 / 关注**（禁转发引导），转发靠内容本身的社交货币属性，不靠 CTA。

结论式收尾定规不动（最后一段连贯文字）。转化引导是**结论段之后的独立一小段**：

- **价值锚定式**：「如果这篇帮你省了排查时间，点个在看让我知道」——先给价值再要动作
- **单动作**：一篇只要一个动作（在看 或 关注），与视频 CTA「价值锚定单动作」定规同思路
- **收藏触发点**：文中至少一处「可收藏资产」——命令速查 / 对比表 / 决策树 / 配置清单（掘金章「获得感」表格的公众号落地），并在转化段点出（「文中的 X 表可以直接收藏」）——收藏是完读之外的强质量信号
- **转发属性写法**（不引导转发，但让内容值得转）：观点段敢下判断、替读者说出他在团队里说不出的话（「这套流程推行不动，问题多半不在工具」）——读者转发的是「我想说的这句话」
- **文末往期关联**：转化段之后放 2-3 篇相关旧文（源稿用 relref，公众号版自动换成平台链接）——读完的人继续读下一篇，直接拉停留时长与关注转化（内容关联是电商「套装」逻辑在内容上的翻版）
- **微信平台红线（判废级）**：
  - ❌ 诱导分享：「分享到朋友圈领取资料」「转发抽奖」
  - ❌ 强制关注：「关注才能看完整版」「关注后台回复 X」
- **转化段不进源 md**（博客版读者看到「点在看」是错位体验，同掘金互动引导只加平台版的分工）：流程 = `make wechat-draft-only` 存草稿 → 后台编辑器在结论段后补转化段 → 群发

## 七、48h 数据回看（优化闭环）

发布后 48 小时内，人工看一次公众号后台数据：**送达 / 打开率 / 读完率 / 分享 / 在看 / 关注净增**。

> 📊 完读率基准线（2026-08-26 调研，推荐算法经验值）：<30% 推荐终止；≥50% 进中级推荐池；>65% 算法持续追加流量。转发率正常区间 1%-3%。回看时对着线定位，不纠结绝对值。

- 结论一句话写进 `link-map.json` 该 slug 的备注（例：「打开 8%，读完 35%，首屏过弯但第 3 节流失」），并**对照基准线归档**：完读 <30% = 算法不推，先修首屏与节奏；30-50% = 及格但没进池，找流失章节
- **连续两篇读完率低于自己历史中位** → 对最近一篇做首屏 + 节奏专项复盘（哪一节流失、小标题间隔、代码块长度），结论同样写回
- **打开率持续低**（标题/摘要问题）与**完读率低**（正文问题）分开归因——打开低改 `wechat_title`/`wechat_digest` 策略，完读低改首屏/节奏
- 不建自动采集（现有数据通道只覆盖视频四平台）；回看习惯跑起来、积累了基线数据，再立采集变更

## 八、发布前留存检查清单（同步公众号前逐条过）

在博客发布检查（SKILL.md 第 9 步）之外，同步公众号前额外过：

- [ ] `wechat_title` 已定稿：≤25 字、钩子前 13 字、非 SEO 长标题直发、无标题党五类
- [ ] `wechat_digest` 已定稿：前 40 字含痛点或硬数字（不填 = 被抓正文前 54 字）
- [ ] 首屏：正文前 150 字内可见问题定义 + 钩子，无寒暄铺垫开头；首屏内有一张图
- [ ] 节奏：二级标题间隔 ≤1200 字；代码块均 ≤15 行，超长者已改「片段 + 完整版入口」
- [ ] 扫读：只读「小标题 + 段首句 + 加粗」逻辑仍成立；段落间过渡无空垫词、无设问
- [ ] 钩子兑现：钩子 → 回收清单逐条核对，无「只承诺不回收」；转场无自问自答
- [ ] 收藏触发：文中至少一处可收藏资产（速查/对比表/决策树），转化段会点到它
- [ ] 往期关联：文末已放 2-3 篇相关旧文（relref，公众号版自动转平台链接）
- [ ] 转化：结论段完整；转化段（单动作、价值锚定、无诱导分享/强制关注）待草稿阶段补入，未写进源稿
- [ ] **发布配置四查**（2026-08-26 定规，逐项核对）：①**作者**已录入（`WECHAT_AUTHOR` 非空，草稿作者栏不空）②**合集**挂对（`--album` 默认 AI；前端类文章传 `album=前端技术`；不挂传 `none`，别让技术文错挂碎碎念）③**原创声明**开（`copyright_type=1` 文字原创；转载/大幅引用他人原文的除外）④**广告开关**与预期一致（群发前在 mp 后台核对流量主文中/文末广告状态——API 建草稿不含此设置，人工确认）
- [ ] 发布方式：先 `make wechat-draft-only`（补转化段后再群发），不直接 `wechat-publish-mp` 自动群发
- [ ] 48h 回看已排期（对照完读率 30/50/65 基准线归档），link-map.json 备注待写

> 数值证据等级（2026-08-26 更新）：标题 ≤25 字 = platform-limits 数据支撑；**首屏 150 字 / 5-15% 跳出 / 20% 阅读率 / 完读 30-50-65 基准线 / 转发 1-3% = 调研数据支撑**（NN/g 眼动研究 + 公众号运营实证）；前 13 字 / 前 40 字 / 1200 字 / 15 行 = 经验值，随 48h 回看数据校准。
