# 图文卡片设计

> ⚠️ **2026-08 已归档**:图文发布管线(`scripts/xiaohongshu/`、`image-text/`、旧第三方发布管线)已删除。本 skill 仅保留卡片**设计规范**(卡片/正文分工、信息分层、对比驱动、去术语化、视觉规范),不再配套预览页/截图/发布脚本。需要实际出图时,用手工 HTML + 浏览器截图导出,图片放 `static/img/xhs-cards/`。

## 何时用

- 把博客长文转成小红书/抖音图文笔记（多张卡片 + 正文）时
- 卡片可读性差、信息堆砌、术语太多，要重做时
- 新建 `image-text/<slug>/preview.html` 预览页时

## 核心原则：卡片与正文职责不同，不能混

| | 卡片（图） | 正文（description） |
|---|---|---|
| **职责** | 秒级抓眼球，让人停下手指 | 深度展开，让人产生行动 |
| **信息量** | 一张卡片**一个核心观点** | 完整说明、互动引导 |
| **阅读方式** | 扫视（1-2 秒）| 精读 |
| **文字占比** | 知识类文字占页面 **≥70%** | 不限 |
| **字号层次** | 3-4 种字号，关键词最大 | emoji 分段 + 列表 |

> 反模式：一张卡片塞 3 个观点（信息平铺，读者抓不住重点）；或正文写太短（没承接卡片的钩子）。

## 卡片信息结构（四层，信息分层）

每张内容卡片按这个骨架组织（CSS 类名对应 `preview.html`）：

1. **核心观点 `.core`**（23-26px 加粗）：一句话讲清这步的核心。用 `<span class="strike">划掉错误做法</span>` + `<span class="accent">蓝色强调正确</span>` 强化对比。
2. **开场白 `.lead`**（13.5px）：用大白话讲清楚「这步在解决什么生活化的问题」。关键短语 `<b>` 加粗，具体例子用 `<span class="ex">` 灰底标。**这是承载「多展示信息」的关键层。**
3. **主体载体**（二选一）：
   - **对比块 `.compare`**：❌ 错误做法（红底）vs ✅ 正确做法（绿底），左右/上下排列
   - **清单 `.details`**：编号列表，每条一句 + 大白话注解
4. **补充细节 `.details`**（13px 灰底 `·` 列表）：2-3 条额外信息（场景判断、降级方案、局限）。

## 高传播手法（技术内容特有）

### 对比驱动
每个工程问题做成 `❌ 常见错误 vs ✅ 正确做法`。技术读者一眼懂且印象深刻——比抽象描述强 10 倍。
- ❌ 块讲「大家常踩的坑 + 后果」
- ✅ 块讲「正确做法 + 关键技术名」

### 翻转卡（误解 vs 真相）
全文最高价值的认知翻转点（如「response_model=Pydantic 不是提示词约束」），单独做一张翻转卡：
- 上半红底 `.flip-side.myth`：常见误解
- 下半蓝底 `.flip-side.truth`：实际情况
- 中间箭头连接

### 代码片段当视觉锚点
状态机骨架那张配真实代码块（5 行核心 + 中文注释），Monokai 着色（`.k` 红 / `.n` 绿 / `.s` 黄 / `.c` 灰）。比箭头图直观，且证明「我有真实代码」提升可信度。

## 去术语化原则

**该保留的术语**（目标读者需要、无可替代）：`function calling`、`Pydantic`、`instructor`、`JSON Schema`、`SSE`、`HTTP`、`WebSocket`、`Postgres`、`LangGraph`、`ReAct`、`API`、`Agent`、代码块内的函数名/状态名。

**该改成中文的**（非必要英文）：

| ❌ 不必要英文 | ✅ 中文 |
|---|---|
| LLM | 大模型 |
| prompt | 提示词 |
| mock | 模拟 |
| registry | 组件库 |
| props | 属性 |
| token | 额度/调用费用 |
| dense / sparse | 稠密向量 / 稀疏向量 |
| hitl / feedback / failed（说明文字里） | 人确认 / 回环 / 失败 |
| uuid | 唯一标识 |
| Schema（非 JSON Schema 语境） | 结构 |

> 判定标准：这个词换个中文，技术读者还能不能懂？能就用中文。代码块内的标识符**保留原样**（那是代码）。

## 卡片叙事递进（9 张通用骨架）

1. **封面**：3-7 字主标题（最大字号）+ 开场钩子（划掉错误认知）+ **五个问题预告清单**（每条大白话说清要解决什么）+ 标签
2. **骨架/总览**：核心观点 + 真实代码块 + 三种出口说明
3-7. **五个工程问题**：每张 = 核心观点 + 开场白 + ❌vs✅ 对比 + 补充
8. **关键澄清**：独立翻转卡（误解 vs 真相）
9. **总结 + CTA**：何时用 + 互动引导（「你卡在哪？评论区聊」）

每张卡片**独立可懂**——即使只看一张，也能 get 一个完整观点。

## 视觉规范

- **字号层次**：核心 23-26px / 开场白 13.5px / 正文 13-14px / 补充 12-13px
- **统一主色**：1 个强调色（#2563eb 蓝）+ 深灰文字（#1e293b），禁止彩虹多色
- **留白**：卡片内容区 padding 24-32px，行距 1.6-1.75，信息别挤
- **画布**：1080×1440（3:4），preview 用 540×720 半尺寸预览
- **主题色条**：每张卡片顶栏左侧 4px 色条区分主题（blue/green/amber/red/purple/slate）

## 字数控制

- 单张卡片文字 80-150 字（含核心+开场+对比+补充），超了就拆
- 正文 description：小红书 ≤1000 字符（含 HTML 标签），抖音不限，视频号 ≤1000

## 调研依据

基于小红书/抖音知识图文最佳实践调研（2026-07）：
- 封面文字占比 ≥70%，主标题 3-7 字
- 爆文公式 = 需求 + 形式 + 互动
- FAB 法则 + 认知对比（使用前后）增强说服力
- 卡片拆分逻辑：封面 → 问题 → 方案 → 对比 → 总结
