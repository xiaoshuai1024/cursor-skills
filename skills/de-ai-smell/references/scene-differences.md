# 场景差异速查表

> de-ai-smell 是公共去味层，**不做场景化执行**。本表供 `blog-writing` / `image-text-cards` / `video-generation` 各自引用——不同文体，去味的禁改边界、力度、正向目标不同。

## 四场景对照

| 维度 | 技术博客 | 小红书图文卡 | 视频口播 | Release Notes |
|------|----------|------------|---------|---------------|
| **禁改边界** | 第二人称「你 / 您」禁用；代码 / 命令 / 版本绝对不动 | 一卡一观点不动；适度 emoji 可留 | 命令 / 参数不动；设问节奏可留 | 版本号 / 变更项不动 |
| **力度** | 中（工程师口吻，减法为主） | 轻-中（可口语，不堆网络黑话） | 轻（短句、口语先行） | 轻（只讲用户效果） |
| **正向目标** | 克制、准确、可扫读、有判断 | 秒抓眼球、一卡一核心、正文展开 | 听得懂、节奏明快、像在说 | 列清变更、验证、限制 |
| **可留的「AI 味」** | 几乎不留 | 适度口语词 | 设问、短句连发 | 条目式结构 |

## 各场景细则

### 技术博客（→ blog-writing）
- 禁第二人称「你 / 您」，用角色词（开发者 / 技术负责人）或客观陈述。
- 资深工程师给同事讲系统的口吻：可以口语，但不俚语。
- 不做报告腔，也不做口播腔。
- 每个 opinion 要有 data / case 支撑（呼应检查清单 L3 内容支撑）。

### 小红书图文卡（→ image-text-cards）
- 卡片：一卡一核心观点，大字抓眼；正文：深度展开，可口语。
- 去术语化：非必要英文用中文（LLM→大模型），术语保留（function calling / Pydantic）。
- ❌vs✅ 对比是核心手法。
- 适度 emoji 可留，但不滥用；禁网络黑话（兜底 / 铁证仍禁）。

### 视频口播（→ video-generation）
- 短句为主，单行字幕。
- **允许设问节奏**（区别于技术博客禁设问）——口播靠设问推进。
- 口语先行，但禁网络黑话。
- 数据从文章抓取，不编。

### Release Notes
- 结构：Breaking → Features → Fixes → Deprecations。
- 每条一句话，只说用户效果。
- 不写发布宣言（「本次版本是系统性升级」删）。
- 版本号、变更项绝对不动。

## 力度档位（参考，非强制流程）

| 档位 | 适用 | 动作 |
|------|------|------|
| 轻（minimal） | 文本基本自然，只去局部模板感 | 删空总结、压过高语气 |
| 中（standard） | 有明显 AI 腔，信息骨架好 | 统一语域、改黑话、必要时并句 |
| 重（aggressive） | L1 禁词密集或多类结构叠加 | 先保真再重写 |

> 力度由问题命中强度决定，不是「想改多重」。技术文档默认不升到「重」。
