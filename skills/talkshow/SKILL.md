# Talkshow（脱口秀式技术讲解）

把技术内容（口播稿 / 文章段落 / 视频分镜）改写成有真实笑点的脱口秀风格——**只在用户点名时启用**。改写的目标不是「变搞笑」，是用幽默修补贴数据里最疼的位置：前 30 秒留存、过桥流失、揭底记忆点。核心讲解段照旧讲透，一个梗都不加。

> 决策依据与试点数据门槛：`openspec/changes/humor-style-research/proposal.md`（幽默=修辞层，不是人设转型）。

## 何时用（点名制）

| 用户说 | 动作 |
|---|---|
| 「用脱口秀的方式讲」「段子风」「幽默版」「加梗」「talkshow」 | 调用本 skill |
| 正常写文章 / 写口播 / 做视频 | **不调用**（blog-writing / video-generation 照常） |

## 硬边界（违反即返工，来自 humor-style-research 提案）

1. **位置限定**：梗优先投三个区——前 30 秒钩子区、段落过桥句、揭底句；炸场档可扩到全片讲解卡，但见第 3 条底线。
2. **类型限定**：只用三类安全梗——**自嘲**（拿自己的翻车开刀；缺省主菜 = **职场自嘲**：打工人共同经历映射技术内容，见 B2 句式包）、**圈内梗**（技术圈共同经历）、**离谱真实案例**（真实事故本身比编的好笑）。禁攻击性幽默、禁刻薄真实雇主/同事、禁与内容无关的插科打诨。
3. **密度档位（2026-08-29 用户重定义）**：
   - **超级炸场 + 职场自嘲（缺省档，点名即此档）**：每卡 2-3 梗、几乎句句有戏，梗型以**职场自嘲为主菜**（打工人共同经历映射技术内容），热梗 + 成品包袱 + 拟人宇宙贯口三路齐上。**密度门禁量化：笑点位 ≥2.5/卡（EP08 基准 2.8），不足即补**。基准样片 = `build/eng-series-ep08-cost/`（2026-08-29 用户验收定规）与 `humor-pilot-exitcode-max/`。
   - **降档选项**（仅用户点名时才降）：标准档（一段 ≤1 梗）/ 加强档（每卡 1-2 梗）。
   - **共同底线**：数据/结论陈述句零玩笑、CTA 与签名句零玩笑、每梗必须挂真实事实且驮一个知识点。密度靠「句句有戏」（语气词、拟人、冷面补刀）+ 概述轮播开场，不靠句句是完整包袱（完整包袱连排观众累、审核警觉）。
   - **职场自嘲边界**：自嘲位只打「我 / 我的系统 / 我的 agent」，不打老板/公司/真人同事；怨气不进数据句与结论，每个梗的落点回到知识点（梗完必有干货收）。
4. **禁区**：签名句、CTA 段、数据陈述句——这些位置出现玩笑 = 掉信任。
5. **真实锚定**：技术梗必须挂在真实机制上（源码行为 / 真实事故 / 真实约定），「素材真实可溯源」规则对段子同样生效。编造行为换笑点 = 违规。
6. **每支片仍是完整讲解**：钩子→回收映射表、三要素 checklist 照常执行，梗不能顶替钩子（梗可以当钩子的壳，回收必须兑现）。

## 工作流（8 步，2026-08-29 定规）

1. **定投放区与档位**：拿现有稿 / 分镜 / 文章，确认档位——**缺省即超级炸场 + 职场自嘲**（降档仅限用户点名）；标出投放位——口播稿标前 30s、各过桥句、各揭底句；**文章标开头 800 字钩子、各节过桥句、结论揭底句 + 禁区清单（数据段/结论/CTA 一次性标出，禁区外默认不放，比视频更保守）**。
2. **联网搜梗（每次写稿必做第一步，缺省档强制）**：开 `references/meme-armory.md` 的 **G 区「联网搜梗引擎」**——① **职场梗定向搜索**（缺省主菜）：按 G 区职场查询模板搜当期职场热梗与吐槽句式（牛马/摸鱼/背锅/画饼/排期类，query 直接抄）；② 泛热梗扫描保时效。新梗按「记录格式」追加进弹药库（梗 + 出处链接 + 搜集日期 + 保质期判断）。③ **对标实抓**：用 douyin-topic skill 的 `search_works.py` 实抓 2-3 个抖音同类高赞作品/头部博主文案，提炼其结构与密度基准，**仿结构与密度、不仿句子**（禁照抄文案，同质化与版权双红线）。组装 = A 区句式 × B2 职场句式包 × 新梗。**禁止只靠弹药库存货**——存货会过期；纯离线环境才允许退化到存货，并在稿头注明。
3. **态度与机制选型**（joke-craft §1-2）：每个投放位先定四态度之一（奇怪/可怕/困难/愚蠢，挂真实事实），再按选择启发式定**一个主机制**（反转/夸张/误导/对比四族），过机制四问（预期/证据/违背/为何仍连贯）。一稿一主机制，副机制至多一个。
4. **多版本竞争写梗**（joke-craft §3-4）：**先写包袱再倒推铺垫；前两版联想直接扔掉，第三版起才许成稿（第三联想规则）**；每个投放位产出 **≥3 个实质不同包袱**（不同机制或不同联想层，禁止同义改写）再择优选一，允许全部否决重开。稿面必须可见 ≥3 版对照与入选理由——无对照产物 = 未执行本步。包袱词不进铺垫句、落包袱句句尾。段内用 Tag 连抖（不换前提、每刀新增画面或风险）。
5. **诊断修梗**（joke-craft §5）：六维审稿表打分（真实/清晰/惊奇/声音/可演/密度 0-3 分），**先修最低维**；单个梗不好笑先判 H1-H6 状态再按对应手术处理（解释过度 = 在说透前半句收住）；修梗按 punch-up 次序，禁止凭感觉堆比喻。收尾过模拟观众三问（毒舌/较真/捧场，结论只作假设）。
6. **真实锚定**：每个梗标注它挂着的真实事实（文件 / 约定 / 事故编号 / 源码行为），标不出的梗删掉。机制四问第④问与本步双保险。
7. **过四道门**：① `make check-ai-smell path=<稿>`（含 2026-08-28 新增「有机生长隐喻」禁词：长成了/长在文件里/从事故里长等，改「搭建/写在/从事故换来」）；② platform-compliance 扫描（词库对梗不豁免，「遥遥领先」「吊打」这类梗本身就是违禁词）；③ 密度自查（按档位数每卡梗数）；④ **读音与水文门（2026-08-28 用户定规）**——读音：多音字逐一核对，TTS 无拼音标注通道一律写稿期规避（量词「行」→「条」；「调用/调命令」→「跑命令/呼叫」；「重/率/得/还」读没把握的换词），合成后抽听验证；水文：每卡必须有「可带走硬信息」（数字/判据/机制/命令至少其一），连续两卡无硬信息 = 水文，返工补实料，禁凑情绪空转卡。
8. **TTS 节拍**（口播稿链路；文章跳过）：**脱口秀稿整体走「乐子哥腔」朗读模式（2026-08-28 用户定规）**——成片朗读参考绷不住的乐子哥语气/音调（E1 声学画像：F0 起伏向 2.2 倍靠、语气词放开、句间零废话衔接），禁止普通朗读腔；**普通模式口播稿仍用现行发布配置，完全不变**。脱口秀稿内部：punch 句 / 揭底句用 `--emo dyn`（tts-emotion-dynamics 角色向量）；**开头钩子句收着（scale 1.0），正文包袱放开（1.3）**——2026-08-28 用户实听定规。合成后人工听感三处：铺垫句停顿、包袱句语气、callback 句衔接；合成声扛不住的段子降级为「仅文案/字幕层」。

## 段子技法速览（详细见弹药库 C 区 + joke-craft.md）

- **预期违背**：铺垫建立预期，包袱打破预期。铺垫越正经，包袱越响——技术讲解天然正经，是优势。
- **三翻四抖**：同方向铺垫三次，第四次反向抖出。清单类内容（通缉名单、报错清单）天然适配。
- **callback**：前面埋过的梗，在结尾意想不到处回收。全片 ≤1 次，回收点放在揭底句或金句，不放 CTA。
- **Tag（段内连抖，joke-craft §4）**：包袱抖完不换前提、不重新解释，从同一发现再挖 1-3 刀，每刀必须有新增画面或风险；不占热梗词配额。与 callback 分工：Tag 在段内，callback 在结尾。

## 与其他 skill 的关系

- **文章链路**：本 skill 同样适用于文章改写——投放按段落功能（开头钩子/节过桥/结论揭底，默认标准档，禁区清单先行），结构骨架、类型、配图仍走 blog-writing（类型不因段子改变）；文章链路过 de-ai-smell 中文句法层（的链/虚动词/类比密度一段 ≤1 一篇 ≤3），joke-craft §6 有双链路落法差异表。点名入口不变：用户不点名，blog-writing 照常，不进本 skill。
- 视频层：deck/口播稿改写后走 video-generation 正常管线；本 skill 只负责梗的生成与守门。
- 门禁归属：de-ai-smell（AI 味）、platform-compliance（违禁词）是发布门禁，本 skill 不豁免它们。
